# Changelog

## sensorstrings 2.0.0

Generated by Claude Opus 5.5

### Breaking changes

#### Removed or renamed functions

- `ss_leaflet_station_map()` is now
  [`ss_map_stations()`](https://centre-for-marine-applied-research.github.io/sensorstrings/reference/ss_map_stations.md).
- `ss_coords_from_ddm_to_dd()` is replaced by
  [`ss_convert_coords_from_ddm_to_dd()`](https://centre-for-marine-applied-research.github.io/sensorstrings/reference/ss_convert_coords_from_ddm_to_dd.md).
  The new function takes a data frame, not a vector. It converts every
  column ending in `_n_ddm`, `_s_ddm`, `_e_ddm` or `_w_ddm`, and takes
  the sign from the hemisphere letter.
- `filter_dat_to_plot()` is now
  [`ss_filter_dat_to_plot()`](https://centre-for-marine-applied-research.github.io/sensorstrings/reference/ss_filter_dat_to_plot.md).
- `ss_create_variable_labels()` and
  `ss_create_variable_labels_no_newline()` are now internal.
- `ss_assemble_region_data()` and `ss_convert_old_log()` have been
  removed.

#### Renamed and reordered arguments

- [`ss_ggplot_variables()`](https://centre-for-marine-applied-research.github.io/sensorstrings/reference/ss_ggplot_variables.md):
  `color_palette` is now `colour_palette`, `color_col` is now
  `colour_col`, and `axis_label_newline` is now `yaxis_newline`.
- [`ss_plot_variables()`](https://centre-for-marine-applied-research.github.io/sensorstrings/reference/ss_plot_variables.md):
  `color_palette` is now `colour_palette`. The `title` argument has been
  removed.
- [`ss_import_data()`](https://centre-for-marine-applied-research.github.io/sensorstrings/reference/ss_import_data.md):
  `input_path` is now `path`.
- [`ss_create_log_from_metadata()`](https://centre-for-marine-applied-research.github.io/sensorstrings/reference/ss_create_log_from_metadata.md):
  `path_export` is now `output_path` and `path_metadata` is now `path`.
  The new order is `(output_path, station, deployment_date, path, ...)`.
- [`ss_set_up_folders()`](https://centre-for-marine-applied-research.github.io/sensorstrings/reference/ss_set_up_folders.md):
  `path` is now `path_output`, and it comes after `station` and
  `depl_date`.
- [`ss_create_template()`](https://centre-for-marine-applied-research.github.io/sensorstrings/reference/ss_create_template.md):
  `station` and `depl_date` no longer have defaults.

#### Changed behaviour

- [`ss_plot_variables()`](https://centre-for-marine-applied-research.github.io/sensorstrings/reference/ss_plot_variables.md)
  now returns a patchwork object instead of a `ggarrange()` figure.
  ggpubr is no longer a dependency.
- [`ss_ggplot_variables()`](https://centre-for-marine-applied-research.github.io/sensorstrings/reference/ss_ggplot_variables.md)
  no longer calls
  [`ggplot2::theme_set()`](https://ggplot2.tidyverse.org/reference/get_theme.html),
  so it leaves your global theme alone.
- [`ss_set_up_folders()`](https://centre-for-marine-applied-research.github.io/sensorstrings/reference/ss_set_up_folders.md)
  and
  [`ss_create_template()`](https://centre-for-marine-applied-research.github.io/sensorstrings/reference/ss_create_template.md)
  now need `depl_date` in `"yyyy-mm-dd"` format.
- [`ss_read_log()`](https://centre-for-marine-applied-research.github.io/sensorstrings/reference/ss_read_log.md)
  stops with an error if the log is not a `.csv`, `.xlsx` or `.xls`
  file.
- [`ss_create_log_from_metadata()`](https://centre-for-marine-applied-research.github.io/sensorstrings/reference/ss_create_log_from_metadata.md)
  stops with an error, instead of a warning, when no rows match the
  station and deployment date.
- `leaflet`, `mooring`, `plotly`, `sf` and `shiny` are now in Suggests.
  Install them to use
  [`ss_map_stations()`](https://centre-for-marine-applied-research.github.io/sensorstrings/reference/ss_map_stations.md),
  [`ss_model_mooring()`](https://centre-for-marine-applied-research.github.io/sensorstrings/reference/ss_model_mooring.md),
  [`ss_open_trimdates_app()`](https://centre-for-marine-applied-research.github.io/sensorstrings/reference/ss_open_trimdates_app.md)
  and the `ss_check_station_*()` functions.
- patchwork 1.3.2 or later is now required.

### New features

- [`ss_compile_vdat_data()`](https://centre-for-marine-applied-research.github.io/sensorstrings/reference/ss_compile_vdat_data.md)
  compiles tilt (`tilt_degree`) as well as depth and temperature.
- [`ss_export_path()`](https://centre-for-marine-applied-research.github.io/sensorstrings/reference/ss_export_path.md)
  and
  [`ss_import_path()`](https://centre-for-marine-applied-research.github.io/sensorstrings/reference/ss_import_path.md)
  take a `path` argument, so they can be used away from the CMAR R
  drive.
- Side-effect functions such as
  [`ss_export_county_files()`](https://centre-for-marine-applied-research.github.io/sensorstrings/reference/ss_export_county_files.md)
  return the paths of the files they write, invisibly.
- Variable names, labels and plot order come from one internal table
  (`ss_vars`), so all functions use the same names.
- Every exported function has a runnable example.

### Bug fixes

- File names with more than one `.` are now read correctly.
- [`ss_compile_vemco_data()`](https://centre-for-marine-applied-research.github.io/sensorstrings/reference/ss_compile_vemco_data.md)
  works on VR2AR files without tilt.
- Duplicate timestamps in vdat files are removed before pivoting, so
  they no longer create list-columns.
- [`ss_parse_log()`](https://centre-for-marine-applied-research.github.io/sensorstrings/reference/ss_parse_log.md)
  warns and keeps the first value when a log has more than one string
  configuration, instead of stopping with an error.
- [`ss_set_up_folders()`](https://centre-for-marine-applied-research.github.io/sensorstrings/reference/ss_set_up_folders.md)
  no longer treats a station as existing when its name only partly
  matches another station’s folder.
- [`ss_import_data()`](https://centre-for-marine-applied-research.github.io/sensorstrings/reference/ss_import_data.md)
  only reads `.rds` files.
- [`ss_plot_variables()`](https://centre-for-marine-applied-research.github.io/sensorstrings/reference/ss_plot_variables.md)
  applies the standard y-limits to
  `dissolved_oxygen_uncorrected_mg_per_l`.
- [`ss_ggplot_variables()`](https://centre-for-marine-applied-research.github.io/sensorstrings/reference/ss_ggplot_variables.md)
  no longer errors on `NA` temperatures.
